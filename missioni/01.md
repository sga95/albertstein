# Missione 1: il primo commit

**Cosa ottieni:** cambi una cosa sul sito e la vedi online un minuto dopo, con il tuo nome sopra.

**Perché conta:** Git è la prima cosa che ti chiedono in qualsiasi team IT, anche in rete e sicurezza. Non serve saperlo a memoria, serve averlo usato per davvero.

## Passi

1. Apri il repository su GitHub e leggi `README.md` e `INIZIA-QUI.md`.
2. Vai su `site/index.html`, clicca la matita (Edit). Cambia la frase sotto il titolo con una tua. Corta, vera, senza aggettivi.
3. In fondo, "Commit changes": scrivi un messaggio tipo `Update home intro`, scegli "Create a new branch" e apri una pull request.
4. Guarda la pull request: dopo un minuto il bot Cloudflare scrive un commento con l'URL di anteprima (Workers Builds). Aprilo. È il sito con la tua modifica, ma non ancora quello vero.
5. Se ti piace, "Merge pull request". Aspetta un minuto, apri albertstein.link e ricarica.
6. Ora apri `site/data/progress.json`, metti `"done": true` sulla missione 1 e fai un secondo commit direttamente su `main` (questa volta senza pull request, così provi anche l'altra strada).

## È fatta quando

- La home dice la tua frase.
- La barra in home ha il primo quadratino arancione.
- Nel CV, sotto "Skills earned on this site", c'è la prima riga.

## Riga che entra nel CV

Git and GitHub: branches, commits, pull requests

## Se ti blocchi

Incolla su claude.ai:

> Sto imparando Git su GitHub dal browser. Ho un repository con un sito statico. Voglio: modificare un file, aprire una pull request, fare merge, poi fare un commit diretto su main. Guidami un passo alla volta, chiedimi cosa vedo prima di dirmi il passo dopo. Non scrivere tu il contenuto, dimmi solo dove cliccare e perché.
